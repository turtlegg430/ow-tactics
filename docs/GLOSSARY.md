# GLOSSARY — 개발 용어 사전

새 용어가 나올 때마다 추가한다. 설명은 처음 듣는 사람도 이해할 수 있게 1~2문장으로.

| 용어 | 뜻 |
|---|---|
| HTML | 웹페이지의 뼈대. 제목, 버튼, 그림처럼 "무엇이 있는지"를 적는 언어. |
| CSS | 웹페이지의 옷. 색, 크기, 배치처럼 "어떻게 보이는지"를 정하는 언어. |
| 자바스크립트 (JavaScript) | 웹페이지의 움직임. 버튼을 누르면 무슨 일이 일어날지 같은 "동작"을 만드는 언어. |
| 시안 / 프로토타입 | 완성 전에 방향을 확인하려고 빠르게 만드는 견본. |
| 버티컬 슬라이스 | 기능 전체를 얕게 만드는 대신, 한 조각(예: 문제 1개)을 처음부터 끝까지 완성도 있게 만드는 방식. |
| 데이터 파일 | 코드와 분리해서 내용만 담아두는 파일. 이 프로젝트에선 문제 내용을 여기에 적어, 코드를 몰라도 문제를 추가할 수 있게 한다. |
| 2.5D / 아이소메트릭 | 2D 그림이지만 비스듬히 내려다본 각도로 그려 입체감을 주는 방식. |
| 마크다운 (Markdown) | `#`, `-`, `|` 같은 간단한 기호로 제목·목록·표를 표시하는 글쓰기 형식. 이 가이드 문서들이 마크다운(.md) 파일이다. |
| CLAUDE.md | Claude Code가 작업을 시작할 때 자동으로 읽는 안내 파일. 프로젝트 규칙과 맥락을 적어둔다. |
| Git | 파일의 변경 기록을 저장하는 도구. 언제 무엇을 바꿨는지 되돌아볼 수 있다. |
| GitHub | Git으로 관리하는 프로젝트를 인터넷에 올려 보관·공유하는 서비스. |
| 저장소 (Repository, 레포) | 프로젝트 파일과 그 변경 기록 전체를 담는 단위. |
| 커밋 (Commit) | 변경 내용을 하나의 저장 지점으로 기록하는 것. 게임의 세이브와 비슷하다. |
| 푸시 (Push) | 내 컴퓨터의 커밋을 GitHub로 올리는 것. |
| 배포 (Deploy) | 만든 프로그램을 다른 사람이 접속해서 쓸 수 있게 인터넷에 올리는 것. |
| GitHub Pages | GitHub 저장소의 웹페이지를 무료로 배포해주는 기능. |
| Claude Code | 내 컴퓨터의 프로젝트 폴더에서 직접 파일을 읽고, 코드를 쓰고, 실행까지 해볼 수 있는 Claude. 데스크톱 앱의 Code 탭에서 쓸 수 있다. |
| SVG | 점과 선, 도형을 좌표로 적어서 그리는 그림 형식. 코드로 맵과 토큰을 그릴 수 있고, 확대해도 깨지지 않는다. 이 프로젝트의 시안 보드를 이걸로 그린다. |
| 컨텍스트 (Context) | Claude가 한 번에 참고하는 대화와 자료의 범위. 대화가 길어질수록 커지고 사용량도 늘어나서, 새 채팅으로 옮기면 가벼워진다. 그래서 중요한 내용은 문서와 메모리에 남겨 둔다. |
| 기술 스택 | 프로그램을 만드는 데 쓰는 언어와 도구의 묶음. 이 프로젝트는 Vite + TypeScript + React + SVG. |
| 프레임워크 | 화면을 만들 때 쓰는 뼈대 도구. 자주 쓰는 구조를 미리 갖춰 둬서 처음부터 다 만들지 않아도 된다. |
| React (리액트) | 가장 널리 쓰이는 화면 프레임워크. 화면을 버튼·체력바·보드 같은 부품(컴포넌트)으로 나눠 만든다. |
| 컴포넌트 (Component) | 화면을 이루는 부품 하나. 한 번 만들면 여러 곳에 다시 쓸 수 있다. |
| TypeScript (타입스크립트) | 자바스크립트에 "이 값은 숫자", "이건 글자" 같은 약속(타입)을 붙인 언어. 약속과 다른 값이 들어가면 실행하기 전에 알려준다. |
| Vite (비트) | 개발 중 미리보기(개발 서버)와 배포용 파일 묶기(빌드)를 해 주는 도구. |
| 빌드 (Build) | 여러 코드 파일을 브라우저가 바로 읽을 수 있게 묶고 줄이는 과정. 결과물은 dist 폴더에 생긴다. |
| 개발 서버 (로컬 미리보기) | 내 컴퓨터에서만 열리는 임시 웹 주소(localhost). 코드를 저장하면 화면이 바로 바뀐다. |
| Node.js | 개발 도구를 내 컴퓨터에서 돌리는 실행기. Vite도 이걸로 돌아간다. |
| npm | Node.js용 패키지를 받아오고 명령을 실행하는 창구. `npm install`, `npm run dev` 같은 명령을 쓴다. |
| 패키지 (Package) | 남이 만들어 공개한 코드 묶음. React와 Vite도 패키지다. 쓰는 패키지 목록은 package.json에 적힌다. |
| GitHub Actions | 푸시 같은 일이 생기면 GitHub가 정해 둔 작업(빌드, 배포 등)을 자동으로 해 주는 기능. 설정은 .github/workflows/ 안의 파일에 적는다. |
| 공개 / 비공개 저장소 | 누구나 볼 수 있는 저장소 / 나와 초대한 사람만 보는 저장소. 이 프로젝트는 공개다. |
| 클론 (Clone) | GitHub 저장소를 변경 기록째로 내 컴퓨터에 복사해 오는 것. |
| 브랜치 (Branch) / main | 저장소 안의 작업 줄기. 기본 줄기 이름이 main이고, 이 프로젝트는 main에 푸시하면 자동 배포된다. |
| README | 저장소 첫 화면에 보이는 소개 문서(README.md). |
| .gitignore | Git이 기록하지 않을 파일 목록. 설치된 도구 폴더(node_modules), 빌드 결과물(dist) 같은 것을 적는다. |
| 라이선스 (License) | 남이 내 코드를 어디까지 써도 되는지 정한 약속. 없으면 볼 수는 있어도 가져다 쓸 권리는 없다. |
| 2단계 인증 (2FA) | 비밀번호에 휴대폰 인증 앱 코드까지 넣어야 로그인되는 방식. |
| noreply 이메일 | GitHub가 주는 공개용 대체 이메일. 커밋에 진짜 이메일 대신 기록된다. |
| 경로 (Path) | 파일이나 폴더의 위치를 적은 주소. 예: `E:\git\ow-tactics`. 개발 도구가 헷갈리지 않게 영어로만 쓰는 게 안전하다. |
| 캔버스 (Canvas) | 도형을 좌표로 기억하는 SVG와 달리 픽셀을 바로 칠하는 그림 방식. 그릴 게 아주 많을 때 빠르다. |
| LTS (장기 지원판) | 오랫동안 보안·버그 수정을 받는 안정 버전. Node.js는 짝수 버전(예: 24)이 LTS가 된다. |
| 터미널 (Terminal) | 글자로 명령을 입력해 컴퓨터를 조작하는 창. Code 탭의 터미널 패널에서 `git push` 같은 명령을 직접 칠 수 있다. |
| 전역 설정 (git config --global) | 이 컴퓨터의 모든 저장소에 똑같이 적용되는 Git 설정. 커밋 작성자 이름·이메일을 여기에 넣었다. |
| Git Credential Manager (자격 증명 관리자) | GitHub 로그인을 브라우저 창으로 처리하고, 승인한 로그인 정보를 윈도우에 저장해 두는 도우미. 한 번 승인하면 다음 푸시부터는 묻지 않는다. |
| safe.directory (믿을 수 있는 폴더) | 주인을 확인할 수 없는 폴더에서도 Git이 작업하도록 허락하는 목록. E 드라이브는 exFAT(파일 주인을 기록하지 않는 저장 방식)라서 저장소 폴더를 여기에 등록했다. |
| 템플릿 (Template) | 새 프로젝트를 빨리 시작하도록 미리 짜 둔 뼈대 파일 묶음. 이 프로젝트는 Vite의 React + TypeScript 템플릿으로 시작했다. |
| 스테이징 (git add) | 다음 커밋에 넣을 변경을 골라 담는 단계. 장바구니에 담기(`git add`)와 계산하기(`git commit`)의 관계와 비슷하다. |
| 줄바꿈 방식 (LF / CRLF) | 줄 끝 표시가 윈도우(CRLF)와 다른 운영체제(LF)에서 다르다. 커밋할 때 나오는 "LF will be replaced by CRLF" 경고는 Git이 알아서 맞춘다는 뜻이라 무시해도 된다. |
| node_modules | `npm install`로 받은 패키지가 들어가는 폴더. 크고 언제든 다시 받을 수 있어서 GitHub에는 올리지 않는다. |
| package-lock.json | 받은 패키지의 정확한 버전을 적어 둔 파일. `npm ci`는 이 파일대로 똑같이 설치해서, 내 컴퓨터와 GitHub Actions가 같은 버전으로 빌드한다. |
| base (배포 경로) | 사이트가 주소의 어느 폴더 아래에 올라가는지 Vite에 알려 주는 설정. 배포 주소가 `.../ow-tactics/`라서 `vite.config.ts`에 `base: '/ow-tactics/'`를 적었다. |
| 린트 (Lint) | 코드를 실행하지 않고 읽기만 해서 실수나 나쁜 습관을 찾아 주는 검사. 이 프로젝트는 oxlint를 쓴다 (`npm run lint`). |
| YAML (.yml) | 들여쓰기와 `이름: 값`으로 설정을 적는 파일 형식. GitHub Actions 워크플로를 이 형식으로 쓴다. |
| 워크플로 (Workflow) | GitHub Actions가 할 일을 순서대로 적은 파일(`.github/workflows/`). 이 프로젝트의 deploy.yml은 설치 → 빌드 → 배포 순서다. |
| 해시 (Hash) | 커밋이나 파일 내용으로 계산한 고유한 긴 문자열(예: 커밋 ID `0af13a1…`). 내용이 조금만 바뀌어도 값이 달라져서, 기록을 다시 쓰면 커밋 ID가 전부 바뀐다. 워크플로에서 부품을 이 값으로 적으면 정확히 그 버전만 쓴다. |
| 원격 저장소 (Remote) / origin | 내 컴퓨터 저장소와 연결된 인터넷 쪽 저장소(GitHub). 기본 이름이 origin이고, 주소는 `git remote -v`로 본다. |
| 작성자 / 커미터 (Author / Committer) | 커밋마다 기록되는 두 사람. 작성자는 변경을 처음 만든 사람, 커미터는 그 커밋을 저장소에 넣은 사람이다. 보통 같다. |
| 기록 다시 쓰기 (History rewrite) | 이미 만든 커밋들을 처음부터 다시 만들며 이름·파일 내용 등을 고치는 작업. 커밋 ID가 전부 바뀌므로 GitHub에 올릴 때 강제 푸시가 필요하다. 이 프로젝트는 `git filter-branch`로 했다. |
| 백업 번들 (Bundle) | 저장소의 모든 커밋과 브랜치를 파일 하나로 묶은 백업(`git bundle`). 이 파일에서 저장소를 그대로 되살릴 수 있다. |
| 강제 푸시 (Force push) | GitHub의 기록을 내 컴퓨터의 기록으로 덮어쓰는 푸시. `--force-with-lease`를 붙이면 "내가 마지막으로 본 뒤로 GitHub 쪽이 바뀌지 않았을 때만" 덮어써서 남의 변경을 실수로 지우지 않는다. |
| 갈라진 기록 (ahead / behind) | 내 컴퓨터와 GitHub의 기록이 서로 다른 상태. `ahead 6`은 내 쪽에만 있는 커밋 6개, `behind 6`은 GitHub 쪽에만 있는 커밋 6개라는 뜻이다. |
| 전역 무시 목록 | 이 컴퓨터의 모든 저장소에 적용되는 .gitignore (`~/.config/git/ignore`). 저장소의 .gitignore와 달리 다른 컴퓨터에는 적용되지 않는다. |
| 실행 기록 (Workflow run) | GitHub Actions가 워크플로를 한 번 돌릴 때마다 남는 기록과 로그. 저장소의 Actions 탭에서 보고 지울 수 있다. |
| 버려진 커밋 (Dangling commit) | 어떤 브랜치도 가리키지 않게 된 커밋. 강제 푸시로 덮어써도 GitHub에는 한동안 남아 커밋 ID로 열릴 수 있다. 이 프로젝트는 저장소를 새로 만들어 없앴다 (D-056). |
| 빈 저장소 (Empty repository) | 커밋이 하나도 없는 저장소. GitHub에서 README·.gitignore를 켜지 않고 만들면 빈 저장소가 되어, 내 컴퓨터의 기록을 보통 푸시로 그대로 올릴 수 있다. |
| 모듈 (Module) | 코드를 역할별로 나눈 파일 하나. 다른 파일에서 `import`로 가져다 쓴다. |
| 순수 함수 | 같은 입력이면 늘 같은 결과를 내고, 화면이나 다른 값은 건드리지 않는 함수. `src/engine/`은 전부 순수 함수라 되감기와 비교가 쉽다. |
| 사건 (Event) / 타임라인 | 결말 재생에서 "1.2초에 아나가 수류탄을 던짐" 같은 일 하나가 사건이고, 사건을 시간순으로 모은 것이 타임라인. 재생 중 t초의 장면은 t초까지의 사건을 적용한 결과다. |
| 스냅숏 (Snapshot) | 한 순간의 상태를 통째로 찍어 둔 것. 문제는 판단 순간의 스냅숏에서 시작한다. |
| 변환 스크립트 | 파일을 읽어 다른 형식으로 바꿔 주는 작은 프로그램. 매핑표 엑셀과 스캔 CSV를 게임용 데이터로 바꾸는 데 쓴다. |
| 개발용 패키지 (devDependency) | 개발할 때만 쓰고 배포판에는 들어가지 않는 패키지. package.json의 devDependencies에 적힌다. |
| 광선 투사 (Ray cast) | 한 점에서 다른 점으로 보이지 않는 선을 쏴서 처음 닿는 곳을 알아내는 계산. 맵 스캐너가 바닥 높이를 잴 때 쓴다. |
| CSV | 쉼표로 칸을 나눈 표 텍스트. 엑셀로도 열린다. |
| 높이 지도 (Heightmap) | 격자 칸마다 바닥 높이를 적은 표. 스캔 결과를 여기서 층으로 나눈다. |
| 워크숍 (Workshop) | 오버워치 사용자 지정 게임 안에서 간단한 규칙(스크립트)을 만드는 기능. |
| 인스펙터 (Workshop Inspector) | 워크숍 변수 값과 그 변화 기록을 보는 창. 기록을 CSV로 클립보드에 복사할 수 있다. |
| 해시 주소 (#) | 주소 뒤 `#` 다음 부분. 페이지를 새로 받지 않고 화면만 바꿀 때 쓴다. 실험실은 `#lab`. |
