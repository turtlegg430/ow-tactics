# GLOSSARY — 개발 용어 사전

새 용어가 나올 때마다 추가한다. 설명은 처음 듣는 사람도 이해할 수 있게 1~2문장으로.

| 용어 | 뜻 |
|---|---|
| HTML | 웹페이지의 뼈대. 제목, 버튼, 그림처럼 "무엇이 있는지"를 적는 언어. |
| CSS | 웹페이지의 옷. 색, 크기, 배치처럼 "어떻게 보이는지"를 정하는 언어. |
| 자바스크립트 (JavaScript) | 웹페이지의 움직임. 버튼을 누르면 무슨 일이 일어날지 같은 "동작"을 만드는 언어. |
| 시안 / 프로토타입 | 완성 전에 방향을 확인하려고 빠르게 만드는 견본. |
| 버티컬 슬라이스 | 기능 전체를 얕게 만드는 대신, 한 조각(예: 문제 1개)을 처음부터 끝까지 완성도 있게 만드는 방식. |
| 데이터 파일 | 코드와 분리해서 내용만 담아두는 파일. 이 프로젝트에선 문제 내용을 여기에 적어, 코드를 몰라도 문제를 추가할 수 있게 한다. |
| 2.5D / 아이소메트릭 | 2D 그림이지만 비스듬히 내려다본 각도로 그려 입체감을 주는 방식. |
| 마크다운 (Markdown) | `#`, `-`, `|` 같은 간단한 기호로 제목·목록·표를 표시하는 글쓰기 형식. 이 가이드 문서들이 마크다운(.md) 파일이다. |
| CLAUDE.md | Claude Code가 작업을 시작할 때 자동으로 읽는 안내 파일. 프로젝트 규칙과 맥락을 적어둔다. |
| Git | 파일의 변경 기록을 저장하는 도구. 언제 무엇을 바꿨는지 되돌아볼 수 있다. |
| GitHub | Git으로 관리하는 프로젝트를 인터넷에 올려 보관·공유하는 서비스. |
| 저장소 (Repository, 레포) | 프로젝트 파일과 그 변경 기록 전체를 담는 단위. |
| 커밋 (Commit) | 변경 내용을 하나의 저장 지점으로 기록하는 것. 게임의 세이브와 비슷하다. |
| 푸시 (Push) | 내 컴퓨터의 커밋을 GitHub로 올리는 것. |
| 배포 (Deploy) | 만든 프로그램을 다른 사람이 접속해서 쓸 수 있게 인터넷에 올리는 것. |
| GitHub Pages | GitHub 저장소의 웹페이지를 무료로 배포해주는 기능. |
| Claude Code | 내 컴퓨터의 프로젝트 폴더에서 직접 파일을 읽고, 코드를 쓰고, 실행까지 해볼 수 있는 Claude. 데스크톱 앱의 Code 탭에서 쓸 수 있다. |
| SVG | 점과 선, 도형을 좌표로 적어서 그리는 그림 형식. 코드로 맵과 토큰을 그릴 수 있고, 확대해도 깨지지 않는다. 이 프로젝트의 시안 보드를 이걸로 그린다. |
| 컨텍스트 (Context) | Claude가 한 번에 참고하는 대화와 자료의 범위. 대화가 길어질수록 커지고 사용량도 늘어나서, 새 채팅으로 옮기면 가벼워진다. 그래서 중요한 내용은 문서와 메모리에 남겨 둔다. |
| 기술 스택 | 프로그램을 만드는 데 쓰는 언어와 도구의 묶음. 이 프로젝트는 Vite + TypeScript + React + SVG. |
| 프레임워크 | 화면을 만들 때 쓰는 뼈대 도구. 자주 쓰는 구조를 미리 갖춰 둬서 처음부터 다 만들지 않아도 된다. |
| React (리액트) | 가장 널리 쓰이는 화면 프레임워크. 화면을 버튼·체력바·보드 같은 부품(컴포넌트)으로 나눠 만든다. |
| 컴포넌트 (Component) | 화면을 이루는 부품 하나. 한 번 만들면 여러 곳에 다시 쓸 수 있다. |
| TypeScript (타입스크립트) | 자바스크립트에 "이 값은 숫자", "이건 글자" 같은 약속(타입)을 붙인 언어. 약속과 다른 값이 들어가면 실행하기 전에 알려준다. |
| Vite (비트) | 개발 중 미리보기(개발 서버)와 배포용 파일 묶기(빌드)를 해 주는 도구. |
| 빌드 (Build) | 여러 코드 파일을 브라우저가 바로 읽을 수 있게 묶고 줄이는 과정. 결과물은 dist 폴더에 생긴다. |
| 개발 서버 (로컬 미리보기) | 내 컴퓨터에서만 열리는 임시 웹 주소(localhost). 코드를 저장하면 화면이 바로 바뀐다. |
| Node.js | 개발 도구를 내 컴퓨터에서 돌리는 실행기. Vite도 이걸로 돌아간다. |
| npm | Node.js용 패키지를 받아오고 명령을 실행하는 창구. `npm install`, `npm run dev` 같은 명령을 쓴다. |
| 패키지 (Package) | 남이 만들어 공개한 코드 묶음. React와 Vite도 패키지다. 쓰는 패키지 목록은 package.json에 적힌다. |
| GitHub Actions | 푸시 같은 일이 생기면 GitHub가 정해 둔 작업(빌드, 배포 등)을 자동으로 해 주는 기능. 설정은 .github/workflows/ 안의 파일에 적는다. |
| 공개 / 비공개 저장소 | 누구나 볼 수 있는 저장소 / 나와 초대한 사람만 보는 저장소. 이 프로젝트는 공개다. |
| 클론 (Clone) | GitHub 저장소를 변경 기록째로 내 컴퓨터에 복사해 오는 것. |
| 브랜치 (Branch) / main | 저장소 안의 작업 줄기. 기본 줄기 이름이 main이고, 이 프로젝트는 main에 푸시하면 자동 배포된다. |
| README | 저장소 첫 화면에 보이는 소개 문서(README.md). |
| .gitignore | Git이 기록하지 않을 파일 목록. 설치된 도구 폴더(node_modules), 빌드 결과물(dist) 같은 것을 적는다. |
| 라이선스 (License) | 남이 내 코드를 어디까지 써도 되는지 정한 약속. 없으면 볼 수는 있어도 가져다 쓸 권리는 없다. |
| 2단계 인증 (2FA) | 비밀번호에 휴대폰 인증 앱 코드까지 넣어야 로그인되는 방식. |
| noreply 이메일 | GitHub가 주는 공개용 대체 이메일. 커밋에 진짜 이메일 대신 기록된다. |
| 경로 (Path) | 파일이나 폴더의 위치를 적은 주소. 예: `E:\git\ow-tactics`. 개발 도구가 헷갈리지 않게 영어로만 쓰는 게 안전하다. |
| 캔버스 (Canvas) | 도형을 좌표로 기억하는 SVG와 달리 픽셀을 바로 칠하는 그림 방식. 그릴 게 아주 많을 때 빠르다. |
