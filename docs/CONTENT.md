# CONTENT — 문제 설계 규칙

최종 수정: 2026-09-30

## 문제 한 개의 흐름
1. 인게임 1인칭 캡처를 먼저 보여준다 ("여기가 어디인지" 먼저 알게)
2. 같은 순간의 탑뷰 보드로 넘어가 상황 제시 (판단에 필요한 정보 전부 표시, 캡처 속 위치와 연결)
3. (선택) 예측 질문
4. 선택지 3~4개 중 선택
5. 선택한 결말 재생
6. 되감기 → 다른 선택(특히 최선)의 결말과 비교
7. 원리 해설

## 채점
- 맞다/틀리다 대신 **최선 / 무난 / 악수** 3단계.
- 모든 선택지에 "왜"를 붙인다.

## 해설 원칙
- "프로가 이렇게 했다"가 아니라 **판단 뒤의 원리**를 설명한다.
  - 나쁜 예: "여기서 들어갔다."
  - 좋은 예: "적 아나의 수면총과 키리코 방울이 빠진 걸 확인했기 때문에 들어갔다."
- 판단 근거가 되는 정보(스킬 상태, 궁 게이지, 체력, 위치)는 전부 화면에 제시해서 "상황 따라 다르다"는 여지를 줄인다.

## 장면 소스: 프로 리플레이 (1차)
**장점**: 수준 높은 판단의 실제 사례. 자유 시점·일시정지로 재료 추출이 쉽다. 정답 루트의 실제 결말이 있다.

**주의점** (진행하면서 보완)
- 프로 플레이는 음성 소통, 팀의 합, 높은 실행력이 전제다. 솔로 큐에서는 그대로 통하지 않을 수 있다 → 해설은 원리 중심으로.
- 프로도 실수한다. 결과가 좋았다고 판단까지 좋았던 건 아니다 → 이유가 선명한 장면을 고른다.
- 리플레이에는 정답 루트의 결말만 있다. 오답 결말은 사용자가 판단해서 구성한다.
- 리플레이는 게임 패치 후 볼 수 없게 될 수 있다 → 장면을 고르면 즉시 기록.

## 리플레이 기록 양식
장면 하나당 아래를 채운다. 캡처 파일은 `장면번호_설명` 식으로 이름을 붙인다.

```
## 장면 기록 #___
- 리플레이 코드:
- 경기 정보(팀, 대회 등, 아는 만큼):
- 패치 / 경기 날짜:
- 맵 / 구역:
- 경기 상황 (공격·수비, 점령률 또는 화물 진행, 남은 시간):
- 타임스탬프(판단 순간):
- 판단의 주인공(영웅):
- 1인칭 화면이 바라보는 방향 (콜아웃 기준):

### 판단 순간의 상태 (10명 모두)
| 영웅 | 팀 | 위치(구역/층) | 체력 | 탄약 | 핵심 스킬 상태 | 궁 게이지 |
|---|---|---|---|---|---|---|
|  | 아군 |  |  |  |  |  |

### 캡처
- [ ] 주인공 1인칭 화면 (판단 순간)
- [ ] 구조가 잘 보이는 각도 (자유 시점)
- [ ] 10명 위치 표시 (구조 캡처 위에 대충 표시해도 됨)
- [ ] 높이가 중요한 곳은 옆에서 수평으로 본 화면 (턱이나 계단 옆에 영웅을 세워 키를 기준 자로)
- [ ] 같은 곳을 두세 방향에서 (가려진 구조 확인용)

### 판단 직전 5~10초에 일어난 일
(누가 어떤 스킬을 어디서 썼나. 해설의 근거가 된다)

### 실제로 일어난 일 (이후 5~10초)

### 선택지 초안
| 선택지 | 채점(최선/무난/악수) | 이렇게 됐을 것 | 이유(원리) |
|---|---|---|---|
|  |  |  |  |

### 이 장면이 가르치는 개념
(예: 턴 교환, 고지대 선점, 궁극기 타이밍 …)
```

## 문제 데이터 (D-058)
- 문제 = 판단 순간 스냅숏(10명의 위치·체력·궁·쿨·딱지, 경기 상황) + 선택지별 사건 목록(이동, 효과, 피해, 딱지, 킬)
- 체력 최대치·쿨타임 같은 수치는 그 경기 시점 값으로 적는다
- 오답 결말은 사용자가 말이나 표로 주면 Claude가 사건 목록으로 옮긴다 (P5부터 편집 도구)

## 1인칭 캡처 (D-060)
- P3 동안은 저장소 밖 폴더에서 개발 서버로만 불러오고, 배포판에는 자리표시 그림
- 리플레이 캡처에는 선수 이름과 킬로그가 찍힌다. 배포판 사용 여부는 P3 완료 전에 결정

## 맵 만들기 (D-059)
1. 보드에 담을 범위를 정한다 (사용자)
2. 워크숍 스캐너로 시험 스캔 → 본 스캔. 인스펙터 기록을 CSV로 복사해 기획 작업 폴더 `스캔\`에 저장
3. 변환 스크립트가 맵 데이터 초안을 만든다
4. StatBanana 오버헤드 지도와 나란히 놓고 검수하고, 이상한 곳만 캡처한다
5. 콜아웃은 사용자가 쓰는 이름을 기준으로 한다
- 오버헤드 지도는 StatBanana 것을 쓴다 (비상업, 원본 재배포 금지, 출처 표기). 저장소에 올리지 않고, 윤곽을 따서 쓰면 README에 출처를 적는다
