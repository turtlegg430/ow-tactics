# WORKFLOW — 역할, 도구, 업데이트 시스템

최종 수정: 2026-09-30 · 상태: **확정** (2026-09-28) — DECISIONS.md D-007~D-009, 저장소·배포 D-050~D-054

## 기본 원칙
- **결정은 대화에서, 기록은 저장소에서.** 저장소(GitHub) 안의 문서가 유일한 원본이다. 대화에서 정한 것도 문서에 옮겨야 "정해진 것"이 된다.
- 기획과 게임 판단은 사용자, 코드와 구현은 Claude.

### 왜 이렇게 나누나
- 채팅은 긴 토론과 빠른 시각 시안에 강하다. 결과물이 파일 하나일 때까지는 여기서 충분하다.
- 파일이 여러 개인 코드베이스가 되면, 채팅에서 코드를 복사해 옮기는 방식은 버전이 꼬인다. Claude Code는 저장소 파일을 직접 읽고 고치고 실행해볼 수 있고, 무엇이 바뀌었는지 비교해서 보여준다.
- 데스크톱 앱의 Code 탭은 터미널 없이 쓸 수 있어 입문자에게 맞다.
- 참고: Claude Code는 Pro 이상 유료 플랜이 필요하다. 2026-09-30 Code 탭 사용 가능 확인.

## 문서 업데이트 시스템

### P2 이전 (저장소 없음)
1. 이 문서 묶음을 claude.ai 프로젝트의 지식(Project knowledge)에 올려둔다.
2. 대화에서 결정이 나면 Claude가 수정된 파일을 새로 만들어 준다.
3. 사용자가 프로젝트 지식의 해당 파일을 새 버전으로 교체한다.

### P2 이후 (저장소 있음)
1. **대화(claude.ai)에서 결정** → 대화 끝에 Claude가 "문서 업데이트 메모"를 작성한다 (어느 파일, 무엇을, 왜).
2. **Claude Code에서 반영** → 사용자가 메모를 붙여넣고 "문서에 반영해줘" → Claude Code가 수정 후 커밋·푸시.
3. **대화 쪽 동기화** → claude.ai 프로젝트 지식에 GitHub 저장소(CLAUDE.md, README.md, docs/)를 연결해 두고, 문서가 바뀌면 Sync 아이콘으로 최신화. 연결한 뒤에는 예전에 손으로 올린 문서를 지워 겹치지 않게 한다.
4. **Claude Code 작업 세션 종료 시** → CLAUDE.md 규칙 7에 따라 요약하고 필요한 문서를 갱신한다.

### 채팅 전환 (인수인계)
대화가 길어지면 사용량 관리를 위해 새 채팅으로 옮긴다 (D-026).
1. **Claude**: 바뀐 문서 수정본(저장소 연결 뒤에는 '문서 업데이트 메모')을 만들고, 메모리를 갱신하고, 새 채팅에 붙여넣을 인수인계 명령어를 쓴다.
2. **사용자**: 프로젝트 지식의 문서를 수정본으로 교체한 뒤(저장소 연결 뒤에는 Claude Code가 저장소에 반영하고 Sync), 같은 프로젝트에서 새 채팅을 열고 인수인계 명령어를 첫 메시지로 보낸다. 작업 중인 파일(매핑표 등)이 있으면 함께 올린다.
3. **새 채팅의 Claude**: CLAUDE.md와 docs/를 읽고 '현재 상태'의 다음 할 일부터 이어간다.
